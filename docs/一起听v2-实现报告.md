## 1. 逐条需求实现说明

### 需求 1｜查看在线玩家和正在听的音乐名

新增 `presence` 包（`ClientProfile` + `PresenceRegistry`）。客户端心跳（`C_PROGRESS`）从「只在房间里发」改成 **房间外也发**，并捎带一份自报身份，服务端把它按 UUID 存进 `PresenceRegistry`。

- 服务端：`S_PRESENCE` 帧 = 全服在线玩家列表，每人带 `nowPlaying` / `nowArtist` / 所在房间标签。
- 客户端：一起听界面第三页「在线」。同时 `/mp who` 也能在纯聊天环境下看到同样的数据。
- 没装 mod 或用老版本客户端的玩家仍会出现在列表里，正在听显示为空、客户端显示「未知客户端」——这是有意的，否则服主会误以为人不在线。

### 需求 2｜查看用户使用的 Mod 名、MP 与 Mu

`ClientProfile` 里带 `mod` / `modName` / `modVersion`，`badge()` 归一成三种角标：

| 角标 | 含义 |
| --- | --- |
| `MP` | modernMP（本项目客户端） |
| `Mu` | MuoniumPlayer |
| `??` | 未上报（老客户端或第三方实现） |

角标显示在成员页、在线页每一行的名字前面，鼠标悬停显示完整 `modName + modVersion`。

> MuoniumPlayer（`C:\MUSIC`）本轮**没有改动**，所以它现在仍显示 `??`。等它接上 `C_PROFILE` 帧就会自动变成 `Mu`，服务端侧不需要再改。

### 需求 3｜查看谁有 VIP、房间里谁有 VIP

`ClientProfile.vipSources` 是客户端上报的「**已登录、能解析会员曲**的平台列表」。客户端侧由 `PartyClient.fillProfile()` 遍历 `ProviderRegistry.all()`，把 `isLoggedIn()` 为真的平台收进来。

- 成员页每行有 VIP 徽标，悬停显示具体平台（如 `netease`）。
- 房间卡片标题栏显示 `VIP N/M`（`PartyRoom.vipCount()`）。
- 术语说明：这里的 VIP 指「**这个人能替房间解析会员曲**」，不是读平台的官方会员标志位——服务端拿不到、也不该拿玩家的账号等级。实际效果一致：有徽标的人就是房间缺链接时能顶上的人。

### 需求 4｜客户端成员管理

一起听界面第二页「成员」，每行右侧按钮随权限出现：

- 房主：授予/撤销管理员、转让房主、移出成员；
- 管理员：移出普通成员；
- 频道里（无房主）：非服务器管理员只有「发起踢出投票」，服务器管理员直接踢。

对应帧：`C_SET_ROLE` / `C_TRANSFER` / `C_KICK` / `C_VOTE_START`。命令行等价物 `/mp admin`、`/mp unadmin`、`/mp transfer`、`/mp kick` 保留。

### 需求 5｜邀请不进聊天框，改成 GUI 待处理邀请

`RoomManager` 收到 `C_INVITE` 后 **不再写聊天框**，而是生成 `PendingInvite` 挂在目标玩家名下，并推一帧 `S_INVITES`。

- 客户端第五页「邀请」列出待处理邀请（邀请人、房名、人数、正在播），两个按钮 → `C_INVITE_ACCEPT` / `C_INVITE_DECLINE`。
- 页签上带未处理数量的小红点。
- 邀请有过期时间，过期条目在下一帧里自然消失。
- 兼容性：如果被邀请方是不认 v2 的老客户端，服务端仍会退回发一条聊天提示，否则那个人永远收不到邀请。

### 需求 6｜公开房间

`Room.open` 字段 + `RoomKind`。

- 开关：`/mp public on|off`，或房间页的「公开」胶囊（`C_SET_PUBLIC`）。默认私密。
- 列表：`S_ROOMS` 帧（`RoomManager.publicRoomsFrame()`），内容含 **房主名、房间名、邀请码、人数、VIP 数、正在播放的曲目**。
- 客户端第四页「发现」：服务器频道置顶，下面是公开房间列表，每行一个「加入」按钮。
- 服主可以用 `publicRoomsEnabled=false` 整体关掉这一页。

### 需求 7｜界面布局与动画

`PartyScreen` 完全重写（约 1800 行），从「一屏堆满」改成 **五页页签**（房间 / 成员 / 在线 / 发现 / 邀请）：

- **卡片高度固定**，不随页面内容变化——之前切页时卡片会伸缩，整块界面跳一下，很廉价；
- 行矩形用池化的 `row()` / `at(i)` 计算（成员行步长 4、成对行 2、邀请行 3），保证不同页的行高有统一节奏；
- 页签下方有**滑动指示器**，切页时指示器平移，内容**只淡入不位移**（位移 + 淡入同时做会显得晃）；
- 投票卡片带 30 秒倒计时进度条；
- 个人暂停是一颗独立胶囊，状态一眼可见；
- 列表超出时滚动，空列表有说明文案而不是空白。

### 需求 8｜个人暂停，恢复时立即对齐进度

`Member.selfPaused` + `C_SELF_PAUSE`。

- 个人暂停只静音**自己**，房间的权威时钟照走，其他人不受影响。`Member.actuallyListening()` 把这类成员从「在听」计数里排掉。
- 客户端侧 `selfPaused` 会挡住 `onTime` / `onResume` / `onSeek` / `startTrack` **所有**开声路径，避免某一条漏网导致偷偷出声。
- 恢复时服务端调 `Room.sendResync()`，单独给这个人发一帧带 `resync:true` 的 `S_PLAY`（含权威位置）。客户端见到 `resync:true` 就清掉个人暂停标记并直接跳到那个位置——**这是「开始时立即同步播放进度」的落点**，不用等下一发心跳。

### 需求 9｜服主 Token 代解析 + 成员贡献会员解析能力

两条独立的路，都在 `Room.requestUrl()` 的优先级链里：

```
服主 Token（服务端自己解析）
  → 开了「贡献会员」的在线成员
  → 声明能解析该平台的成员
  → 点歌人
  → 房间管理者
  → 广播全房
```

**服主 Token**：`MpConfig.serverTokens`（平台 → 凭据）。新增 `resolve` 包：

- `NeteaseTokenApi` —— 网易云 weapi 的双层 AES-CBC + RSA 签名，`songUrl(token, songId, timeout)` 返回直链和已服务时长；
- `ServerResolver` —— 2 线程守护池 + `inFlight` 去重（同一首歌并发点播只解析一次），结果先过 `SourceGuard.isPublicHttpUrl`（挡内网地址）再 `hop` 回主线程下发；
- 其它平台走 `resolverEndpoints` 通用模板，占位符 `{songId}` / `{id}` / `{source}` / `{token}`，响应可以是纯文本 URL 或 JSON（依次找 `url`、`data.url`、`data[0].url`）。

**贡献会员**：客户端设置里新增开关「贡献会员解析能力」（`MusicSettings.partyContributeVip`，默认关）。开启后只是把 `contributeVip=true` 报给服务端，服务端在缺链接时**优先问这些人**。走的仍是原来的 `S_URL_NEEDED` → `C_URL_SUPPLY`：客户端在**本机**解析出带签名、有时效的直链再上传。**cookie / MUSIC_U 永远不离开本机**，详见第 6 节。

### 需求 10｜一起听封禁

`/mp ban <玩家> <原因> <时长>`，仅服务器管理员可用。配套 `/mp unban <玩家>`、`/mp bans`。

- 新增 `ban` 包：`BanEntry` + `BanList`，落盘 `mpsync-bans.json`，UUID 与玩家名两种匹配（离线玩家也能先封）；
- 时长解析在 `util/Durations`，写得很宽容：`30m` / `2h` / `7d` / `30分钟` / `2小时` / `永久` / 纯数字（按分钟）都认；`0` = 永久，解析失败返回 `INVALID` 并提示用法；
- 参数顺序不敏感：`/mp ban Steve 刷屏 30m` 和 `/mp ban Steve 30m 刷屏` 都能用，不写时长按永久；
- 被封的人：`S_BANNED` 帧下发原因和剩余时长，客户端界面直接显示封禁横幅并禁掉所有操作；已经在房间里的会被踢出（`enforceBan()`），并且挡住重新加入；
- `BanList.purge()` 定期清理过期条目。

## 2. 附加需求｜服务器频道

### 频道本身

`RoomKind.CHANNEL` —— 一个 `owner == null` 的特殊房间，全服共用，`/mp channel` 或发现页置顶入口加入（`C_CHANNEL_JOIN`）。

- 所有人都能加入、都能点歌；
- 歌单由**服务器管理员**管理（`Room.controls()` 在频道里改判服务器管理员，而不是房主/房管）；
- **人均 3 首**上限（`channelMaxPerMember`，`Room.perMemberCap()`），频道是全服共用的，不设这一档一个人就能塞满队列；
- 成员离开/被踢不会解散频道（`leave` / `kick` 对频道不 `drop`）。

### 投票切歌

非管理员在频道里按「下一首」时，`C_NEXT` 自动转成一次切歌投票（`VoteSession`）。

- 聊天框广播：`[一起听] XXX 想要切换歌曲《歌名》，回「/mp agree」表示同意（30 秒内，需 N/M 票）`；
- GUI 里同时出现投票卡片，带同意/反对按钮和倒计时条；
- 通过门槛：同意票 **严格大于** 在线人数的 50%（`needed(e) = floor(e * ratio) + 1`）；
- 30 秒窗口结束展示结果并执行；
- **注定失败的投票立刻结算**（`hopeless()`）——剩下的人全投同意也不够票时没必要再等满 30 秒。

### 投票踢人

`/mp vote kick <玩家>` 或成员页按钮。

- 门槛 **80% 以上**；
- **分母排除当事人**（`voteEligible(v)`）——否则小房间里 80% 等于永远踢不掉人；
- 没通过则进入 **1 小时冷却**（`voteKickCooldownMs`），期间不能再对同一个人发起，这就是需求里「不满足票数则放入冷却，避免乱踢，此方案需超过 1 小时生效」；
- 少于 `voteMinMembers`（默认 2）人时不开投票。

`Proto.VERSION` 1 → 2。版本号本身不做硬性拦截，只作为客户端「能不能显示这些页」的判据。

### 新增 C2S

| 帧 | 用途 |
| --- | --- |
| `profile` | 上报客户端身份：mod 名/版本、可解析平台、是否贡献会员 |
| `presence` | 请求全服在线快照 |
| `rooms` | 请求公开房间列表 |
| `set_public` | 把自己的房间设为公开/私密 |
| `invites` | 请求待处理邀请 |
| `invite_accept` / `invite_decline` | 处理邀请 |
| `self_pause` | 个人暂停 / 恢复 |

| `vote_start` | 发起投票（切歌 / 踢人） |
| `vote_cast` | 投票表态 |

### 新增 S2C

| 帧 | 用途 |
| --- | --- |
| `presence` | 全服在线玩家 + 正在听 + 客户端角标 + VIP |
| `rooms` | 公开房间列表（含频道） |
| `invites` | 待处理邀请列表 |
| `vote` | 进行中/刚结束的投票状态与倒计时 |

| 帧 | 新增字段 |

## 4. 服务端新增配置（`config/mpsync.json`）

### 公开房间与频道

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `publicRoomsEnabled` | `true` | 是否允许公开房间与发现页 |
| `channelEnabled` | `true` | 是否开启服务器频道 |
| `channelName` | `服务器频道` | 频道显示名 |
| `maxChannelMembers` | `0` | 频道人数上限，0 = 不限 |
| `channelMaxPerMember` | `3` | 频道内每人同时挂在歌单上的曲目数 |

### 投票

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `voteWindowMs` | `30000` | 投票窗口 |
| `voteSkipRatio` | `0.5` | 切歌门槛（严格大于该比例） |
| `voteKickRatio` | `0.8` | 踢人门槛 |
| `voteKickCooldownMs` | `3600000` | 踢人投票失败后的冷却（1 小时） |
| `voteMinMembers` | `2` | 少于这么多人不开投票 |

### 代解析

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `serverTokens` | `{}` | 平台 → 凭据。**敏感数据**，见使用指导 |
| `resolverEndpoints` | `{}` | 平台 → 解析接口 URL 模板 |
| `serverResolveTimeoutMs` | `12000` | 服务端单次代解析超时 |
| `preferContributors` | `true` | 缺链接时优先问贡献会员的成员 |

### 同步阈值（上一轮引入，v2 起由服务端在 `hello` 里统一下发）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `clockGraceMs` | `4000` | 命令帧之后的时钟静默窗，这段时间不发心跳 |
| `softDriftMs` | `2500` | 软偏差：只做静默微调，不许硬 seek |
| `hardDriftMs` | `6000` | 硬偏差：才允许硬 seek |
| `resyncCooldownMs` | `10000` | 两次硬 seek 之间的最小间隔 |
| `driftConfirmHits` | `2` | 连续命中多少次才动手 |

这五项统一由服务端下发，是为了让同一个房间里的 modernMP、MuoniumPlayer、各个游戏版本**口径一致**——否则会出现「同一房间有人跳有人不跳」。老客户端读不到就用自带默认值，数值与服务端默认值相同。

## 6. 三处刻意的取舍（请知情）

### 6.1 聊天框投票没有做成可点击按钮

需求原文是「玩家点击后即可参加投票」。实际做成了：**聊天框广播纯文本提示 + 打字 `/mp agree` 表态 + GUI 投票卡片按钮点击**。

理由：`ClickEvent` 的构造 API 在 1.20.1 → 26.2 之间变了三次（构造器签名、枚举位置、`Component` 工厂都动过），要在 12 个注入点上分别适配四个游戏版本 × 四个加载器，跨版本编译风险和维护成本都会明显上升，而 GUI 卡片已经提供了「点一下就投票」的体验。**装了客户端 mod 的玩家点 GUI 就行，纯服务端玩家打一行字。**

如果你确实要可点击聊天消息，这一项可以单独做，代价是每个平台模块里加一层 `ClickEvent` 适配。

### 6.2 「贡献会员」不上传 cookie —— 这是按需求做的，但实现方式值得说清

需求写的是「开启后不上传 cookies，而是解析音乐返回音频数据流」。

实际实现：客户端在本机解析出**带签名、有时效的直链**上传给服务端，服务端把直链转发给房间。**没有** 走「客户端把音频字节流中继给服务端再分发」这条路。

理由：真的中继音频流意味着贡献者的上行带宽要承载全房播放（一个 320kbps 的房间 8 个人 = 2.5Mbps 持续上行），家用网络撑不住，而且贡献者一断线全房立刻静音。直链方案下 cookie 同样不出本机（**这是需求的核心目的**），带宽由平台 CDN 承担，贡献者掉线也只影响下一首。

安全边界：上传的直链会过 `SourceGuard.isPublicHttpUrl` 和 `minStreamDurationRatio`（防止有人拿 30 秒试听片段冒充整曲让全房听）。

### 6.3 服务器管理员的判据

core 刻意不碰任何平台的权限 API（这是「一份 core 编进 16 个模块」的前提）。所以服务器管理员靠 `/mp` 命令层传进来的 operator 标志，缓存在 `RoomManager.operators`。

代价：**管理员进服后需要先敲一次任意 `/mp` 命令**（比如 `/mp info`），GUI 里的管理按钮才会出现；下线即清。这对服主是一次性的动作，但如果你希望免掉它，需要在四个平台模块里各加一小段「玩家登录时查一次权限」的代码——core 保持不变。

### 6.4 MuoniumPlayer 未改动

`C:\MUSIC` 的 MuoniumPlayer 本轮没动。它连上 v2 服务端一切照常工作（v2 对 v1 客户端向后兼容），只是在成员列表里显示 `??` / 「未知客户端」，也不会出现 VIP 徽标和贡献会员能力。

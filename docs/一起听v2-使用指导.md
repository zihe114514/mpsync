# 一起听 使用指导（v2）

适用版本：服务端 mpsync **1.3.0**，客户端 modernMP **2.2** 或 MuoniumPlayer **1.4.0**。
支持 Minecraft **1.20.1 / 1.21.1 / 1.21.11 / 26.2**，加载器 **Fabric / Forge / NeoForge / Paper**。

---

## 一、安装

### 服务端

从 `构建产物\服务端mod-mpsync` 里挑与你服务器**完全对应**的那一个 jar，放进 `mods/`（Fabric/Forge/NeoForge）或 `plugins/`（Paper）：

```
mpsync-<MC版本>-<加载器>-1.3.0.jar
```

例：1.21.1 的 NeoForge 服务器 → `1.21.1neoforge__mpsync-1.21.1-neoforge-1.3.0.jar`（丢进 mods 前可以把 `1.21.1neoforge__` 前缀去掉，那只是产物目录里用来分辨来源的）。

**服务端 16 个 jar 必须是同一个版本号。** 不同版本的 core 混跑不会报错，但房间行为会不一致——这是踩过的坑，所以现在构建脚本自带新旧校验。

首次启动会生成 `config/mpsync.json`（Paper 是 `plugins/mpsync/mpsync.json`）。

### 客户端

两个客户端都已支持完整 v2，任选其一，同一个房间里可以混着用：

| 客户端 | 版本 | jar |
| --- | --- | --- |
| modernMP | **2.2** | `构建产物\客户端-modernMP\<版本>-<加载器>__musicplayer-*.jar` |
| MuoniumPlayer | **1.4.0** | `C:\MUSIC\dist\MuoniumPlayer-<MC版本>-<加载器>-1.4.0.jar` |

MuoniumPlayer 覆盖 1.20.1（Fabric / Forge）与 1.21.1 · 1.21.11 · 26.2（Fabric / NeoForge），共 8 个 jar。

老版本客户端也能连（能听、能点歌、命令都能用），只是看不到本次新增的界面，
并且在别人的成员列表里显示成 `??`。

## 二、GUI 页签怎么用

- **modernMP**：打开音乐播放器 → 一起听，顶部五个页签。
- **MuoniumPlayer**：打开播放器面板 → 一起听 → 「一起听 · 服务器房间」，顶部六个页签
  （把 modernMP 的「房间」页拆成了 **房间** + **歌单** 两页，其余一一对应）。

下面按 modernMP 的五页讲，MuoniumPlayer 的差异随文标出。

### 1. 房间

当前房间的状态中心：房名、邀请码、正在播放、进度、成员数、`VIP N/M`。

- **公开** 胶囊：把房间挂到「发现」页，别人不用邀请码也能进；
- **个人暂停** 胶囊：只静音自己，房间照放（详见第五节）；
- 房主/房管额外有播放控制（暂停/恢复/上一首/下一首/清空歌单）；
- 频道里出现的投票卡片也在这一页，带 30 秒倒计时条。

MuoniumPlayer 的差异：这一页只放房间信息 + 进度条 + 播放控制 + 五个操作键
（链接点歌 / 邀请玩家 / 个人暂停 / 同步一次 / 退出房间），**歌单在第 2 个页签**；
「公开 / 设为公开」和「复制邀请码」在房名右边；投票卡与封禁通知是从顶部升起的横幅。
右上角常驻一个「贡献会员解析」开关（见第六节路二）—— 它是账号级授权，跟房间无关，
所以放在标题栏而不是某一页里。

### 2. 成员

每行：客户端角标 + 名字 + 状态 + VIP 徽标。

| 角标 | 含义 |
| --- | --- |
| `MP` | modernMP |
| `Mu` | MuoniumPlayer |
| `??` | 没上报（老版本客户端或没装 mod） |

右侧按钮按你的权限出现：授予/撤销管理员、转让房主、移出成员；在频道里普通成员看到的是「发起踢出投票」。

MuoniumPlayer 的差异：角标跟在名字后面（`Steve  Mu`），第二行是「角色 · 客户端与版本 · 在听什么」，
VIP 徽标是名字右边那颗小胶囊（有人开了贡献会员时显示「贡献」而不是「VIP」）。

VIP 徽标的含义是「**这个人能替房间解析会员曲**」——他登录了某个音乐平台账号。悬停能看到具体平台。

### 3. 在线

全服在线玩家 + 各自正在听的歌 + 所在房间。不在任何房间的人也会列出来。纯聊天环境下用 `/mp who` 看同样的信息。

MuoniumPlayer 的差异：每行右边多一个「邀请」按钮，你在房间里时可以直接从这里邀请对方，
不必回到「邀请玩家」输入框打名字。这一页只在面板打开时向服务端要数据（1 秒一次），关掉就停。

### 4. 发现

- 顶部是 **服务器频道** 入口（全服公开大房间）；
- 下面是所有 **公开房间**：房主名、房名、人数、VIP 数、正在播放，每行一个「加入」按钮。

服主可以用 `publicRoomsEnabled=false` 整体关掉这一页。

MuoniumPlayer 的差异：频道入口是顶部一张卡（含「每人最多同时点 N 首」），公开房间列表在下面，
房间满了按钮会变成灰色的「已满」。

### 5. 邀请

别人邀请你时**不再刷聊天框**，而是进这一页，页签上带未处理数量的小红点。每条邀请显示邀请人、房名、人数、正在播，两个按钮：接受 / 拒绝。邀请会过期，过期的自动消失。

MuoniumPlayer 的差异：页签上直接写数量（「邀请 2」），按钮是「接受 / 忽略」。
连到**旧版 v1 服务端**时这一页会是空的，那种情况下收到的邀请仍然显示在「房间」页大厅态的那张卡上。

## 三、命令表

```
/mp create [房名]         创建房间
/mp join <邀请码>         加入房间
/mp channel               加入服务器频道（全服公开大房间）
/mp public [on|off]       把自己的房间设为公开 / 私密
/mp invite <玩家>         邀请玩家（对方在一起听界面里处理）
/mp leave | /mp disband   离开 | 解散（房主）
/mp admin <玩家> | /mp unadmin <玩家>   授予/撤销管理员
/mp transfer <玩家> | /mp kick <玩家>   转让房主 | 移出成员
/mp pause | resume | skip | prev | clear
/mp play <序号> | /mp seek <秒> | /mp repeat <off|one|all>
/mp vote skip | /mp vote kick <玩家>    频道内发起投票
/mp agree | /mp deny      对进行中的投票表态
/mp info | /mp queue | /mp who         房间信息 | 歌单 | 在线在听
```

管理员专用：

```
/mp ban <玩家> <原因> <时长>
/mp unban <玩家>
/mp bans
/mp list
```

**点歌**在音乐播放器界面里做，命令行不提供搜索点歌。

## 四、服务器频道

`/mp channel` 或发现页顶部入口进入。这是一个全服共用的大房间：

- 所有人都能加入、都能点歌；
- 歌单由**服务器管理员**管理；
- **每人同时只能挂 3 首**（可配）；
- 没有房主，人走光也不解散。

### 投票切歌（50% 以上）

普通成员按「下一首」不会直接切，而是发起一次投票：

1. 聊天框广播：`[一起听] XXX 想要切换歌曲《歌名》，回「/mp agree」表示同意（30 秒内，需 N/M 票）`
2. 装了客户端 mod 的人在房间页看到投票卡片，直接点按钮；没装的人打 `/mp agree`（反对是 `/mp deny`）
3. 30 秒后出结果。同意票**严格大于**在线人数的 50% 才切歌。
4. 如果剩下的人全投同意也不够票，投票会**立刻**结算失败，不干等 30 秒。

> 为什么要打字：可点击的聊天消息在四个游戏版本之间 API 变过三次，为了不让跨版本编译变脆，这一版做成了纯文本 + GUI 按钮。装 mod 的玩家点一下就行。

### 投票踢人（80% 以上）

`/mp vote kick <玩家>` 或成员页按钮。

- 需要 **80% 以上**同意；
- **票数分母不含被投的那个人**（否则小房间里永远踢不掉）；
- 没通过 → 该玩家进入 **1 小时冷却**，期间不能再对他发起；
- 房间少于 2 人不开投票。

## 五、个人暂停

房间页的「个人暂停」胶囊。按下之后：

- 只有你静音，房间的进度照走，别人不受影响；
- 成员列表里你会显示为「个人暂停」，不计入「在听」人数；
- **再按一次恢复时，服务端会单独给你补一帧权威进度，你直接跳到全房当前位置**，不用等下一次心跳。

这就是「临时离开一下」的正确用法——不要用房间暂停，那会把所有人一起停掉。

## 六、服主配置（`config/mpsync.json`）

### 6.1 给没有会员的玩家解析会员曲

有两条路，可以同时开。

#### 路一：服主自己配 Token

```json
{
  "serverTokens": {
    "netease": "MUSIC_U=你的MUSIC_U值"
  },
  "serverResolveTimeoutMs": 12000
}
```

网易云填 `MUSIC_U`，整段 cookie（`"MUSIC_U=xxx; __csrf=yyy"`）也认。配好之后，房间里没人有会员时服务端会自己去解析，玩家侧完全无感。

> ⚠️ **这是敏感数据。** 它等价于你自己的会员账号：
> - 谁能读服务器文件谁就能拿走它，**别放共享主机 / 别提交进 git 仓库**；
> - 玩家永远拿不到它——下发给客户端的只有解析出来的那条带签名的临时直链；
> - 建议用一个专门的小号，不要用主账号。

其它平台走通用模板：

```json
{
  "resolverEndpoints": {
    "qq": "https://你自己的解析服务/qq/url?id={songId}&token={token}"
  },
  "serverTokens": {
    "qq": "给那个解析服务的凭据"
  }
}
```

占位符：`{songId}`（等价 `{id}`）、`{source}`、`{token}`。响应可以是纯文本的一条 URL，也可以是 JSON（依次找 `url`、`data.url`、`data[0].url`）。解析出来的地址仍会被校验必须是公网 http(s)，指不到内网。

服务端**只内置网易云**一家的签名逻辑，其它平台必须靠 `resolverEndpoints`。第三方接口挂了会自动退回向客户端要链接。

#### 路二：让有会员的玩家「贡献解析能力」

玩家自己在 **音乐播放器 → 设置 → 「贡献会员解析能力」** 打开（默认关）。

打开后：

- 房间缺链接时，服务端**优先问这些人**；
- 他们的客户端在**本机**解析出直链再上传，**cookie / MUSIC_U 永远不离开自己的电脑**；
- 上传的是带签名、有时效的临时地址，不是账号凭据；
- 不会占用贡献者的上行带宽（音频由平台 CDN 直发给每个人）。

服主侧开关：`preferContributors`（默认 `true`）。关掉就退回老行为：先问点歌人、再问房管、最后广播全房。

### 6.2 频道与投票

```json
{
  "channelEnabled": true,
  "channelName": "服务器频道",
  "maxChannelMembers": 0,
  "channelMaxPerMember": 3,
  "voteWindowMs": 30000,
  "voteSkipRatio": 0.5,
  "voteKickRatio": 0.8,
  "voteKickCooldownMs": 3600000,
  "voteMinMembers": 2,
  "publicRoomsEnabled": true
}
```

`maxChannelMembers: 0` = 不限人数。`voteSkipRatio` 是「严格大于」，`0.5` 就是「过半」。

### 6.3 同步阈值（网络差时来回跳进度的那一档）

```json
{
  "clockGraceMs": 4000,
  "softDriftMs": 2500,
  "hardDriftMs": 6000,
  "resyncCooldownMs": 10000,
  "driftConfirmHits": 2
}
```

这五项由**服务端统一下发**给所有客户端，所以同一个房间里 modernMP、MuoniumPlayer、各个游戏版本用的是同一套判据，不会出现「有人跳有人不跳」。

调参思路（如果玩家还是抱怨进度乱跳）：

| 现象 | 调法 |
| --- | --- |
| 换歌后前几秒集体乱跳 | 加大 `clockGraceMs`（4000 → 6000） |
| 播放中偶发硬跳 | 加大 `hardDriftMs`、加大 `driftConfirmHits`（2 → 3） |
| 跳得太频繁 | 加大 `resyncCooldownMs`（10000 → 20000） |
| 大家明显脱节但一直不校准 | 减小 `hardDriftMs`（6000 → 4500） |

### 6.4 限制播放平台（可选）

```json
{ "allowedSources": ["netease"] }
```

留空 = 不限制（默认）。服务端不取流，客户端支持哪个平台房间就能放哪个平台，这一项只是给你一个收窄的开关。

当前两个客户端已知令牌：`netease`、`qq`、`kugou`、`gd`、`bilibili`、`youtube`、`kuwo`、
`migu`、`qianqian`、`soda`、`fivesing`、`jamendo`、`joox`、`apple`、`customapi`。
如果还要收窄 `allowedHosts`，可参考 `SourceGuard.DEFAULT_HOSTS`；其中已包含
Bilibili（`bilivideo.com` / `bilivideo.cn` / `hdslb.com`）与 YouTube
（`googlevideo.com` / `ytimg.com`）的 CDN 后缀。`customapi` 需要按你自己的接口再补域名。

## 七、封禁

仅服务器管理员：

```
/mp ban <玩家> <原因> <时长>
```

时长写得比较宽容，下面都认：

| 写法 | 含义 |
| --- | --- |
| `30m` / `30分钟` | 30 分钟 |
| `2h` / `2小时` | 2 小时 |
| `7d` / `7天` | 7 天 |
| `永久` / `0` | 永久 |
| `30`（纯数字） | 30 分钟 |

原因和时长的**顺序不敏感**，不写时长按永久：

```
/mp ban Steve 刷屏点歌 30m
/mp ban Steve 30m 刷屏点歌
/mp ban Steve 恶意切歌
```

效果：被封的人立刻被踢出房间，界面上显示封禁横幅（原因 + 剩余时长），也进不了任何房间和频道。封禁记录落盘在 `mpsync-bans.json`，重启保留，过期自动清理。

解封 `/mp unban <玩家>`，查看列表 `/mp bans`。

> 管理员判据：**管理员进服后需要先敲一次任意 `/mp` 命令**（比如 `/mp info`），客户端 GUI 里的管理按钮才会出现。这是 core 不碰平台权限 API 换来的代价，命令本身随时可用，只是 GUI 按钮要等这一次握手。

## 八、常见问题

**Q：为什么我在成员列表里是 `??`？**
用的是老版本客户端或者 MuoniumPlayer。功能不受影响，只是不上报身份。

**Q：为什么有人有 VIP 徽标我没有？**
徽标表示「登录了某个音乐平台账号、能替房间解析会员曲」。在音乐播放器里登录平台账号就会出现。

**Q：房间里没人有会员，会员曲怎么办？**
服主配了 `serverTokens` 就由服务端解析；没配就得房间里有人有会员（最好把「贡献会员解析能力」打开）。都没有则跳过这首。

**Q：为什么点了「下一首」没切歌？**
你在频道里且不是服务器管理员，触发了投票。等 30 秒或等票数够。

**Q：投票踢人失败了，为什么不能马上再投？**
1 小时冷却，防止连续乱踢。

**Q：进度还是来回跳。**
先确认服务端是 1.2.0 及以上（阈值是服务端下发的），再按 6.3 的表调参。

**Q：能把 `serverTokens` 提交进 git 吗？**
不能。见 6.1 的警告。
